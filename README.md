
# Frontend Interview Preparation Kit

A structured, hands-on repository for preparing for frontend developer interviews. It includes JavaScript fundamentals, coding problems, polyfills, DSA, React, Next.js, browser concepts, API networking, performance, frontend system design, testing, and revision notes.

The goal is to build strong fundamentals, improve problem-solving skills, and become confident in frontend interviews.

## Repository structure

- `01-javascript/` — language fundamentals, coding questions, polyfills, async JavaScript.
- `02-dsa/` — data structures and algorithms grouped by patterns.
- `03-html-css/` — semantic HTML, CSS, accessibility, layouts.
- `04-react-js/` — React concepts, hooks, rendering, state management.
- `05-next-js/` — App Router, rendering, data fetching, caching, SEO.
- `06-browser-web-fundamentals/` — browser behavior, storage, networking, security.
- `07-api-networking/` — REST, fetch, errors, cancellation, retries.
- `08-performance-and-seo/` — Core Web Vitals and optimization.
- `09-frontend-system-design/` — frontend architecture and common design exercises.
- `10-testing/` — Jest, React Testing Library, mocking, test scenarios.
- `11-machine-coding-notes/` — reusable approach and checklists.
- `12-interview-experiences/` — technical and behavioral interview notes.
- `13-revision/` — progress and revision tracking.

> React machine-coding implementations belong in the separate `react-machine-coding` repository. This repository keeps concepts, problem-solving notes, and interview preparation in one place.

## Suggested workflow

1. Read the problem statement before looking at a solution.
2. Attempt it independently and write down the approach.
3. Implement the solution and add meaningful test cases.
4. Record time and space complexity where applicable.
5. Explain the solution aloud as if in an interview.
6. Revisit difficult problems after 1 day, 1 week, and 1 month.

## 🧠 My Approach to Solving Problems

For every coding problem:

1. Understand the requirements and constraints.
2. Explain the approach before writing code.
3. Implement a clear and readable solution.
4. Test normal cases and edge cases.
5. Analyze time and space complexity.
6. Identify possible optimizations.
7. Explain the solution as if answering an interviewer.
